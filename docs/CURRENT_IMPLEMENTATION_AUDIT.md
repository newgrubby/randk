## 2. Главная структурная проблема: филиал = город

**Сейчас:** `Branch.slug` имеет тип `CitySlug`, то есть один филиал жёстко равен одному городу.

**Требуется:** 3 города и 3 физических офиса — по одному в каждом городе.

Текущая модель этого выразить не может: у неё нет уровня «офис». Это не косметическая
правка — затрагивает типы, контент, страницы городов, карту, микроразметку и навигацию.

**План:** ввести `Office` как самостоятельную сущность и `City` как группу офисов.
Страница города выводит список своих офисов.

## 3. Каталог перекошен в сторону английского

**Сейчас:** 7 «программ», из которых две — языковые (`inostrannye-yazyki`, `angliyskiy-yazyk`).
Английский занимает отдельную карточку наравне с целым направлением «иностранные языки»,
остальных языков нет вовсе.

**На старом сайте** есть отдельные страницы: английский, немецкий, французский, испанский,
итальянский, китайский, а в текстах встречаются японский, арабский, турецкий, русский как
иностранный и норвежский.

**План:** вынести языки в отдельную сущность `Language` с собственным разделом `/languages`,
а `programs` оставить для образовательных направлений (экзамены, репетиторство, дошкольное,
развивающее, логопед, психолог, корпоративное).

## 4. Собственный сбор заявок подлежит удалению

**Сейчас в проекте есть:** `POST /api/lead`, Zod-схема заявки, адаптер Telegram, реестр
адаптеров, формы на 6 страниц, квиз с отправкой телефона, honeypot, лимит частоты,
сохранение UTM, модальное окно с формой, согласие на обработку ПДн.

Всё это работает, но клиенту неудобно обрабатывать заявки самостоятельно.

**План:** удалить приём заявок целиком (`api/lead`, `server/notifiers`, `lib/lead-schema`,
`lib/utm`, `forms/*`) и заменить единым контактным модальным окном: выбор города → выбор
офиса → телефон, звонок, копирование номера, VK, MAX, маршрут.

**Побочный положительный эффект:** без API-маршрутов становится возможен статический экспорт.

предположение, а не подтверждённый факт. Помечено в `ASSUMPTIONS.md`.

(`scripts/generate-placeholders.mjs`). Людей, интерьеров и текста на них нет.

документация переезжает в `docs/IMAGE_ASSETS.md`.

## 12. План точечной доработки

1. Модель данных: `City` + `Office` (3 офиса), `Language` (6 активных + 5 скрытых),
   `Program` (образовательные направления) с флагами `active`, `confirmed`,
   `showInNavigation`, `showInSitemap`.
2. Удаление приёма заявок, замена на контактное модальное окно и мобильную панель.
3. Точечная доработка главной: тексты первого экрана, кнопки, блок языков, три офиса.
   Композиция и порядок секций сохраняются.
4. Новые страницы по единым шаблонам: язык, направление, город.
5. Изображения: структура каталогов, композиции для языков и офисов, документация.
6. SEO: `LocalBusiness` на каждый офис, manifest, обновлённый sitemap, редиректы.
7. Режимы сборки: статический экспорт по умолчанию, standalone как альтернатива.
8. Проверки: lint, typecheck, build, адаптивность, доступность.

**Что сознательно не делается:** новый макет, новая палитра, новая сетка, замена
анимационной библиотеки, переписывание работающих компонентов ради единообразия.
