# HOSTING_OPTIONS — размещение в российской инфраструктуре

Проект остаётся на Next.js. Поддерживаются два режима сборки, переключаемые
переменной `BUILD_TARGET` в `next.config.ts`.

---

## Краткий вывод

**Рекомендуется вариант 1 — статическая сборка.** После удаления приёма заявок
в проекте не осталось ничего, что требует постоянно работающего Node.js-сервера,
поэтому сайт можно разместить на обычном Linux-хостинге REG.RU без потери качества.

## Вариант 1 — статическая сборка (REG.RU и любой обычный хостинг)

### Сборка

```bash
npm ci && npm run build
```

Результат — папка `out/` (около 5 МБ), включая `.htaccess` с 39 правилами редиректа.

### Публикация

1. Открыть файловый менеджер или FTP панели REG.RU.
2. Загрузить **содержимое** папки `out/` в корень сайта (обычно `public_html` или `www/<домен>`).
   Загружать нужно именно содержимое, а не саму папку.
3. Убедиться, что файл `.htaccess` загрузился — многие FTP-клиенты скрывают файлы,
   начинающиеся с точки. Включите отображение скрытых файлов.
4. Проверить, что открывается `https://randkcenter.ru/` и `https://randkcenter.ru/languages/german/`.
5. Проверить редирект: `https://randkcenter.ru/nemeckiy_yazyk` должен вести на `/languages/german`.

### Требования к хостингу

- Apache с включёнными `mod_rewrite`, `mod_headers`, `mod_expires` (стандартно для REG.RU);
- SSL-сертификат (Let's Encrypt подключается в панели бесплатно);
- PHP **не требуется**, Node.js на сервере **не требуется**.

### Обновление сайта

Пересобрать локально и заново загрузить содержимое `out/`. База данных отсутствует,
поэтому потерять данные при обновлении невозможно.

### Ограничение

Метаданные строятся при сборке, поэтому любое изменение контента требует
пересборки и повторной загрузки. Для сайта, который меняется несколько раз в год,
это не проблема.

## Вариант 2 — standalone (VPS или облачный Node.js-хостинг)

Нужен, если позже вернётся приём заявок, появится админ-панель или потребуется
серверная логика (например, актуальное расписание из внешнего источника).

### Сборка

```bash
npm ci && npm run build:standalone
```

Результат: `.next/standalone/` + `.next/static/` + `public/`.

### Запуск на сервере

```bash
NODE_ENV=production PORT=3000 node server.js
```

Процесс держать под `pm2` или systemd.

### Docker

```bash
docker build -t randk-center --build-arg NEXT_PUBLIC_SITE_URL=https://randkcenter.ru .
```

```bash
docker run -d -p 3000:3000 --env-file .env.production --restart unless-stopped randk-center
```

`Dockerfile` уже собирает образ в режиме standalone.

### Nginx перед приложением

```nginx
server {
    server_name randkcenter.ru www.randkcenter.ru;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

### Подходящие площадки в России

- VPS REG.RU, Timeweb Cloud, Selectel, Yandex Cloud (Compute Cloud);
- Yandex Cloud Serverless Containers — при использовании Docker-образа.

⚠️ **Обычный PHP shared-хостинг для этого варианта не подходит:** нужен постоянно
работающий Node.js-процесс, которого на таких тарифах нет.

## Сравнение

| Критерий                | Статический экспорт             | Standalone                                       |
| ----------------------- | ------------------------------- | ------------------------------------------------ |
| Тип хостинга            | обычный shared                  | VPS / Node.js / Docker                           |
| Стоимость               | минимальная                     | выше                                             |
| Настройка               | загрузить папку                 | развернуть сервис, настроить прокси и автозапуск |
| Обновление контента     | пересборка + загрузка           | пересборка + перезапуск                          |
| Редиректы               | `.htaccess`                     | `next.config.ts`                                 |
| Оптимизация изображений | отключена                       | включена                                         |
| Отказоустойчивость      | статика почти не падает         | зависит от процесса                              |
| Приём заявок в будущем  | потребует перехода на вариант 2 | доступен сразу                                   |

## Смена режима

Переключение выполняется одной переменной и не требует правок кода:

```bash
BUILD_TARGET=standalone next build
```

или готовой командой:

```bash
npm run build:standalone
```

Список редиректов при этом остаётся единым — `src/config/redirects.ts`. В режиме
standalone его читает `next.config.ts`, в статическом — генератор `.htaccess`.
Разойтись они не могут.
